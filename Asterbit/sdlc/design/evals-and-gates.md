# შეფასება და კარიბჭეები — მენიუ v0

> **სტატუსი:** ჩარჩო. კონკრეტული არჩევანი Spec-ის დამტკიცების შემდეგ კეთდება (`/sdlc-evaluate`, design mode), რადგან მანამდე არ ვიცით, რას ვაშენებთ.

## 1. ორი სიტყვა

**Gate (დეტერმინისტული კარიბჭე)** — შემოწმება, რომელიც ყოველთვის ერთსა და იმავე პასუხს იძლევა და exit code-ით მთავრდება (გასვლის კოდი: 0 = გაიარა, სხვა რიცხვი = ვერ გაიარა). მაგალითად: ტესტები, lint, ტიპების შემოწმება, საიდუმლოებების სკანერი. მისი „დაყოლიება" შეუძლებელია.

**Eval (შეფასება)** — შემოწმება იქ, სადაც პასუხი ერთმნიშვნელოვანი არ არის: მაგალითად, AI აგენტმა სწორად უპასუხა თუ არა მომხმარებელს. ხშირად მოდელი აფასებს მოდელს, ამიტომ თავად ეს შემოწმებაც შემოწმებას საჭიროებს.

## 2. წესები

1. დეტერმინისტული შემოწმება მოდელით შეფასებაზე ადრე მოდის. თუ რამე exit code-ით მოწმდება, მოდელს არ ვაფასებინებთ.
2. Spec-ის ყოველ მიღების კრიტერიუმს ყველაზე იაფი საიმედო შემოწმება შეესაბამება.
3. ყოველი ახალი კარიბჭე „იწვრთნება": ჯერ სუფთა მაგალითი უნდა გაიაროს, შემდეგ განზრახ ჩადებული შეცდომა უნდა დაიჭიროს. გაუწვრთნელი კარიბჭე მტკიცებულება არ არის.
4. „ვერ გაეშვა" და „გაიარა" სხვადასხვა რამაა და ცალ-ცალკე იწერება.
5. ვასწორებთ კოდს და არა კარიბჭეს.

## 4. როგორ ეშვება (ADR-0006)

დეტერმინისტული კარიბჭეები `docs/gates.json`-შია (Phase 7a-ში შენთან ერთად ირჩევა), და მათ `python3 sdlc/checks/run_gates.py` უშვებს. თითო კარიბჭე სამიდან ერთ-ერთ შედეგს იღებს: PASS, FAIL ან INCONCLUSIVE. თუ კარიბჭე ტესტებს ითვლის, „0 ტესტი" მწვანედ არასდროს ითვლება. ყოველ ტესტსა და eval-ზე ერთი დამატებითი კითხვა ისმის: აშკარად არასწორ შედეგზეც ხომ არ გაივლიდა? თუ გაივლიდა, ის არაფერს განასხვავებს და უნდა გაძლიერდეს (Anthropic-ის `skill-creator` grader-ის იდეა).

## 5. ძრავის საკუთარი evals (playbook-იდან)

playbook-ის მიხედვით, აგენტის მართვის კონფიგურაცია (AGENTS.md, skills, hook-ები) კოდივით უნდა შემოწმდეს: 20–50 რეალური დავალება მოსალოდნელი შედეგით, რომლებიც კონფიგურაციის ყოველ ცვლილებაზე ეშვება, ხოლო ყოველი ინციდენტი ახალ eval-ად იქცევა. CI უკვე არსებობს, ამიტომ ეს აღარ არის დაბლოკილი. evals-ს პროდუქტის პირველი ნამდვილი დავალებებიდან ავაწყობთ (საცდელი გაშვება გაუქმდა, 2026-10-08), რადგან ძრავში ახალი რამ მხოლოდ დაკვირვებულ შეცდომაზე ან შენს მოთხოვნაზე ემატება (`tasks/todo.md` → Parked).
