TITLE: Billing changes (general splitting 21.10)
ID: 193003556

 Requirements for changes in billing 
New optional checkbox By number of days should be added in scales nomenclature. Splitting tariff scales according to scale code subperiods before calculation should be corrected – volumes for each subperiod in tariff scales with By number of days NOT checked should be calculated according volumes in scale code subperiods, not according number of days.
If billing data by profile includes more than one month it should be splitted in the way that in each split should include only data for one calendar month
Example:
Period in billing data by profile: 01.01.2024 – 10.02.2024
The system should divide it into two subperiods:
01.01.2024 – 31.01.2024
01.02.2024 – 10.02.2024
The system should combine separate records for billing data by profile if they include data for the same month
Example:
Period in billing data by profile: 01.01.2024 – 10.01.2024
Period in billing data by profile: 11.01.2024 – 31.01.2024
The system should combine them in one subperiod:
01.01.2024 – 31.01.2024
After calculation of the invoice the system should splits all price components which use billing data by scales according all other price components which use billing data by scales using logic for number of days . The system also should calculate old and new meter readings, but mark them with * symbol. In the splitting process the system should ignore discounts (discount should be included in the same split as the price component with which the discount is connected). For price components with discount the system should combine volumes from all rows for the period and present them as one row with Volumes, Single price and Value.
For all other price components the system should not split anything.
For all price components with application model Over time and level Point of Delivery should record row for each POD in detailed invoice data
Calculation over time should consider billing group invocie number (1-4) 
Partial invoicing new logic for profiles splitting/merging flow
Discount row should be ordered after its price component for each period for each POD
POD → Block for billing check 
For examples, please check SubPeriodsV2.xlsx
