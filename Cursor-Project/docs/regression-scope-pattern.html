რეგრესიის სკოუპის რანგი

რანგი და Jira-ს Regression Scope ერთი გადაწყვეტილებაა. HIGHEST არის Version 1 და პირველ ტალღაში ეშვება. HIGH არის Version 1.1. MEDIUM არის Version 1.2. LOW არ არსებობს.

ერთი კითხვა თუ ეს ქეისი ჩავარდება, დარჩება არასწორი დარიცხვა, არასწორი ვალი ან არასწორი მიწოდება?

გადაწყვეტის გზა

კითხვები ზემოდან ქვემოთ მიდის. პირველი დადებითი პასუხი რანგს აფიქსირებს.

1

ჩავარდნა ცვლის დარიცხულ თანხას, ვალს, ან იმას, ვის ერიცხება და ჩართულია თუ არა მიწოდება?

დიახ — HIGHEST. ინვოისი, ვალდებულება, ჩათვლა, გაუქმება, ჯარიმა, დეპოზიტი, მიწოდების გათიშვის ნიშანი.

2

თავად თანხას არ არიცხავს, მაგრამ ამ ჯაჭვის შესასვლელი ან მომიჯნავე პროცესია?

დიახ — HIGH. კონტრაქტი, POD-ის შექმნა, ხელახალი ხელმოწერა, კორექტირება, შეხსენება, არხის კონფიგურაცია, xEnergie.

3

საქმე ეხება კატალოგს, წაკითხვას, წერილს ან კლიენტის ძირითად მონაცემებს, და არც ერთი მათგანი თანხას არ ქმნის?

დიახ — MEDIUM. ფასის კომპონენტის შექმნა, კლიენტის შექმნა, ელფოსტა, გაყიდვების პორტალის წაკითხვა.

4

რჩება მხოლოდ ეკრანი, ჯგუფი, რომელიც კონტრაქტს არ ბლოკავს, ან ველის ფორმატი?

სკოუპის გარეთ. სია, დაკავშირებული ჯგუფი, ტელეფონის სიგრძე, მეტა-შემოწმება.

რა იქმნება Jira-ში

ერთი ქეისი, ერთი შედეგი ჯერ რანგი წყდება. შემდეგ ერთ რანგში ერთი REG ქეისი იქმნება თითო განსხვავებულ შედეგზე. იგივე არასწორი ნაშთის, იგივე მხარის ან იგივე მიწოდების მეორე ვარიანტი, რომელიც მხოლოდ რაოდენობას, პერიოდს ან იმავე სახის მეორე ობიექტს ცვლის, Jira-ში არ იქმნება და ფაილში რჩება.

HIGHEST და Version 1 ერთი ფაქტია. დარეგისტრირებული HIGHEST პირველ ტალღაში ეშვება. ფულადი ვარიანტის Version 1.1-ში გადატანა ტალღას არ ამცირებს: Version 1.1 ნიშნავს, რომ ქეისი თანხას არ ამოწმებს.

რას წარმოადგენს ეს მოდელი ეს ოთხი საფეხური Confluence-ში პრიორიტეტის ველად არ წერია. ეს ანალიზის წესია: რომელი ჩავარდნა უტოვებს მომხმარებელს არასწორ ვალს ან არასწორ მიწოდებას. რანგს არ განსაზღვრავს ავტომატიზაციის, გვერდის ან API-ის უბრალო არსებობა.
