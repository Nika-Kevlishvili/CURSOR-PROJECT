# Frontend Page Object Model (POM) Instructions

When the user provides an HTML file or HTML snippet of a page, generate a fully structured Playwright Page Object Model class following the conventions below. The output must be ready to use — no placeholders, no TODOs.

---

## Page Mode: Create vs Edit

Every domain in this project has two page variants: a **create page** and an **edit page**. The user will always specify which one they need.

### File placement rules

| User says | Save file to | Class name suffix |
|---|---|---|
| "create page" | `src/frontend/pom/createPOM/` | `Create` — e.g. `CustomerCreate` |
| "edit page" | `src/frontend/pom/editPOM/` | `Edit` — e.g. `CustomerEdit` |

### Behavioral differences

**Create page:**
- All fields are enabled and fillable
- Primary action button is a "Create" / "Save" / "Submit" button
- Include all input locators and their corresponding fill/select methods
- The constructor does **not** receive an entity ID

**Edit page:**
- Some fields may be **disabled or read-only** in the HTML (look for `disabled`, `readonly`, `[disabled]`, `class="disabled"`, `pointer-events: none`, `opacity` attributes)
- Declare locators for disabled fields as `readonly` properties but **do not include fill/interaction methods for them**
- Add a comment `// read-only in edit mode` next to disabled locators
- The primary action button is typically "Save" / "Update" / "Edit" — not "Create"
- Include an `openEditMode()` method if there is an "Edit" button that unlocks the form

```typescript
// Example: disabled field in edit mode — declare but do not interact
readonly contractNumber: Locator; // read-only in edit mode

// Fields that remain editable in edit mode get full interaction methods
private async setStatus(status: statusType) {
    await this.dropdown.select_phxBaseDropdown('Status', status);
}
```

### After creating any POM file, always register it in `PageObjects.ts`

1. Add an `import` at the top of [pom/PageObjects.ts](pom/PageObjects.ts)
2. Add a `public readonly` property with a logical camelCase name
3. Instantiate it in the constructor

```typescript
// Import
import { CustomerCreate } from './createPOM/CustomerCreate';

// Property
public readonly customerCreate: CustomerCreate;

// Constructor
this.customerCreate = new CustomerCreate(page, envVariables, dropdown);
```

## Core Rules

### 1. Identify All Interactive Elements From the HTML
Scan the HTML for every interactive element and categorize them:
- **Inputs** (`<input>`, `<textarea>`) — text fields, date pickers, search boxes
- **Buttons** (`<button>`, `<a role="button">`) — actions, confirms, cancels, submits
- **Dropdowns** — custom components: `<phx-base-dropdown>`, `<phx-with-request-dropdown>`, `<phx-dropdown>`, `<phx-multiselect-dropdown>`, `<mat-select>`, native `<select>`
- **Checkboxes / Radio buttons** — `<input type="checkbox">`, `<input type="radio">`, `<phx-checkbox>`, labeled via `getByLabel()`
- **Tabs / Navigation links** — `<a>`, `<phx-tab>`, `[role="tab"]`
- **Tables** — `<tbody>`, `<tr>` for result sets
- **Modal triggers** — buttons that open dialogs or side panels

## File Structure

```typescript
import { expect, Locator, Page } from "@playwright/test";
import { dropdownSelector } from "../../utils/dropdownSelector";
import { ENV_VARIABLES } from "../../fixtures/base";

// 1. Define TypeScript union types for every constrained set of values
type statusType = 'Draft' | 'Active' | 'Terminated';

// 2. Define a parameter object type for complex public methods
type CreateEntityOptions = {
    status: statusType,
    name?: string,
}

export class EntityName {
    page: Page;
    private dropdown: dropdownSelector;
    private sharedDict: ENV_VARIABLES;

    // 3. Declare ALL locators as readonly class properties
    readonly createButton: Locator;
    readonly nameInput: Locator;
    readonly saveButton: Locator;
    readonly confirmButton: Locator;

    constructor(page: Page, sharedDict: ENV_VARIABLES, dropdownSelector: dropdownSelector) {
        this.page = page;
        this.sharedDict = sharedDict;
        this.dropdown = dropdownSelector;

        // 4. Initialize every locator in the constructor
        this.createButton = this.page.locator('#createButtonId');
        this.nameInput = this.page.locator('#nameInputId');
        this.saveButton = this.page.getByRole('button', { name: 'Save' });
        this.confirmButton = this.page.getByRole('button', { name: 'Confirm' });
    }

    // 5. Private methods — one atomic action per method
    private async fillName(name: string) {
        await this.nameInput.click();
        await this.nameInput.fill(name);
    }

    private async selectStatus(status: statusType) {
        await this.dropdown.select_phxBaseDropdown('Status', status);
    }

    // 6. Public methods — orchestrate private methods into full workflows
    async createEntity(options: CreateEntityOptions) {
        await this.createButton.click();
        await this.fillName(options.name ?? 'default name');
        await this.selectStatus(options.status);
        await this.saveButton.click();
        await this.confirmButton.click();
    }
}
```

## Locator Strategy (Priority Order)

Use the **first matching strategy** from this list:

| Priority | When to use | Example |
|---|---|---|
| 1 | Element has a unique `id` | `page.locator('#mat-input-4')` |
| 2 | Element is a semantic role (button, link, textbox) | `page.getByRole('button', { name: 'Save' })` |
| 3 | Element is associated with a label | `page.getByLabel('Invoice date')` |
| 4 | Element is a custom component with a label text | `page.locator('phx-input').filter({ hasText: 'Name' }).locator('#inputId')` |
| 5 | Element requires positional disambiguation | `page.locator('phx-base-dropdown').nth(2)` |
| 6 | Element needs CSS/attribute selectors | `page.locator('input.mat-datepicker-input').nth(0)` |

**Never use XPath unless there is no alternative.**

## Dropdown Handling

The application uses several custom dropdown components. Always route through the `dropdownSelector` utility — never interact with dropdown internals directly in the POM class.

```typescript
// phx-with-request-dropdown (search-based, async options)
await this.dropdown.selectphxWithRequestDropdown('Field Label', 'Option Value');

// phx-base-dropdown (static list)
await this.dropdown.select_phxBaseDropdown('Field Label', 'Option Value');

// phx-multiselect-dropdown
await this.dropdown.Select_PhxMultiselectDropdown('Field Label', 'Option Value');

// phx-dropdown
await this.dropdown.SelectPhxDropdown('Field Label', 'Option Value');
```

For radio buttons and labeled checkboxes, use `page.getByLabel()` or `page.locator('phx-checkbox').filter({ hasText: 'Label' })`:

```typescript
await this.page.getByLabel('One Time').check();
await this.page.locator('phx-checkbox').filter({ hasText: 'For volumes' }).locator('div').nth(1).click();
```

## Method Visibility Rules

| Visibility | When to use |
|---|---|
| `private` | Fills a single field, selects a single dropdown, handles a single UI interaction |
| `public` | Represents a complete user workflow (create, edit, search, submit) |

Never expose atomic locator interactions as public methods unless they are independently reusable across different workflows in the same class.

## TypeScript Type Conventions

- Define **union types** for every field that has a fixed set of allowed values (dropdowns, radio buttons, statuses):
  ```typescript
  type executionType = 'Manual' | 'Immediately' | 'Exact Date';
  ```

- Define **date string types** using template literals when date format is strict:
  ```typescript
  type DateString = `${number}${number}.${number}${number}.${number}${number}${number}${number}`;
  ```

- Group all parameters for a public method into a **single typed options object**:
  ```typescript
  type CreateOptions = { status: statusType, name?: string, startDate?: DateString }
  async createEntity(options: CreateOptions) { ... }
  ```

- Mark optional fields with `?` when the UI does not require them.

## Class Decomposition Rules

Split a single page into **multiple tab classes** when:
- The page has multiple distinct tabs (Tab 1, Tab 2, Tab 3...)
- Each tab has 5+ unique fields
- A tab's fields are not referenced by other tabs

Create a **facade/orchestrator class** that imports and delegates to tab classes:

```typescript
// ProductContract.ts (facade)
export class ProductContract {
    private tab1: ProductContractTab1;
    private tab2: ProductContractTab2;

    constructor(page, sharedDict, dropdown) {
        this.tab1 = new ProductContractTab1(page, sharedDict, dropdown);
        this.tab2 = new ProductContractTab2(page);
    }

    async createContract(params: ContractParameters) {
        await this.tab1.setBasicFields(params);
        await this.tab2.setAdditionalFields();
        await this.page.getByRole('button', { name: 'Create' }).click();
    }
}
```

## Shared State (`ENV_VARIABLES`)

When a created entity's ID or value must be referenced by subsequent test steps (e.g., saved contract numbers, POD identifiers), persist them in `sharedDict`:

```typescript
// After creation, read back and store the generated value
const value = await this.page.locator('#contractNumber').inputValue();
this.sharedDict.productContracts.push(value);
```

Only store values that are explicitly needed downstream. Do not store UI state.

## Waiting and Async Patterns

- Prefer Playwright's built-in auto-waiting; avoid `page.waitForTimeout()` except for polling loops.
- For polling (e.g., waiting for background job completion), use a `while` loop with a max timeout and `setTimeout`:
  ```typescript
  const maxWait = 600; // seconds
  const start = Date.now();
  while ((Date.now() - start) < maxWait * 1000) {
      await this.reloadButton.click();
      if (await this.resultTable.isVisible()) break;
      await new Promise(r => setTimeout(r, 15000));
  }
  ```
- Use `expect(locator).not.toBeVisible()` to wait for loaders to disappear before proceeding.
- Use `dispatchEvent('click')` instead of `.click()` when the element has pointer-events disabled or is behind an overlay:
  ```typescript
  await this.page.getByLabel(criteria).dispatchEvent('click');
  ```

## Naming Conventions

| Element | Convention | Example |
|---|---|---|
| Class | PascalCase | `ProductContract`, `StandardBillingRun` |
| Locator properties | camelCase, descriptive noun | `saveButton`, `nameInput`, `draftInvoicesTable` |
| Private methods | camelCase, verb phrase | `fillName()`, `selectStatus()`, `setGridOperator()` |
| Public methods | camelCase, verb phrase | `createContract()`, `submitBillingRun()` |
| Type aliases | camelCase | `contractStatuses`, `executionType` |
| Options types | PascalCase + suffix | `CreateContractOptions`, `BillingRunParameters` |

## Output Format When Given HTML

When the user provides an HTML file or snippet, produce:

1. **TypeScript union types** for every dropdown, radio group, or select found in the HTML
2. **A parameter object type** for the main create/submit action
3. **A class** with:
   - All interactive elements declared as `readonly` locator properties
   - All locators initialized in the constructor using the priority strategy above
   - One `private` method per logical field group (dates, dropdowns, text inputs)
   - One or more `public` methods representing full user workflows
4. If the page has tabs, split into separate tab files + one facade class

Do not generate test files. Generate only the POM class(es).
