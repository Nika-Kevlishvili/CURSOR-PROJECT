# FILES — ყველა ფაილი: რისთვისაა და რას აკეთებს

> **ვისთვის:** მფლობელისა და თანამშრომლებისთვის — ვისაც პროექტის აგებულების გაგება სჭირდება.
> **წესი:** ფაილის დამატების, გადატანის ან სახელის შეცვლისას ეს რუკა იმავე ცვლილებაში ახლდება. ყველა ბმული რეპოს ფაილზე მიუთითებს.

რეპოში ფაილები ოთხ ჯგუფად იყოფა. პირველი ადამიანებისთვისაა: სახელმძღვანელო, შეთანხმება, თანამშრომლის გზამკვლევი და დღიური. მეორე AI აგენტისთვისაა (Cursor, Claude-ის მოდელებზე): წესები, ეტაპების ბრძანებები, დამხმარე აგენტები და დაცვა. მესამე პროექტის ოფიციალური ჩანაწერებია: სად ვართ, რა გადავწყვიტეთ, რა დარჩა და რა გვახსოვს. მეოთხე ძრავის ბიბლიოთეკაა: ცარიელი ფორმები (თარგები), დიზაინები და კვლევა. თითქმის ყველა ფაილი markdown-ია (ჩვეულებრივი ტექსტი სათაურებით, სიებითა და ცხრილებით), ამიტომ Cursor-შიც, Obsidian-შიც და GitHub-ზეც ერთნაირად იკითხება.

## `.cursor/` — ძრავა Cursor-ში ([ADR-0008](decisions/0008-cursor-support.md))

ეს საქაღალდე მხოლოდ მაშინ ჩაიტვირთება, როცა Cursor-ში `Asterbit` თავად არის გახსნილი საქაღალდე (და არა ის, რომელშიც ის დევს).

- [`hooks.json`](../.cursor/hooks.json) — hook-ების ჩართვა (hook — ავტომატური ჩამრთველი, რომელიც განსაზღვრულ მომენტში თავისით ეშვება): სესიის დასაწყისი, ყოველი shell-ბრძანების წინ (`beforeShellExecution`), ყოველი ფაილის წაკითხვის, ჩაწერის, წაშლისა და shell-ის წინ (`preToolUse`), ხელსაწყოს შემდეგ, შეკუმშვამდე და ქვეაგენტის დაწყება/დასრულებისას. ორივე დამცავი მოვლენა `failClosed`-ია: თუ hook გაფუჭდა, მოქმედება იბლოკება.
- [`cli.json`](../.cursor/cli.json) — Cursor CLI-ის (ტერმინალის ვერსიის) უფლებები: რა შეიძლება თავისით და რა აკრძალულია (საიდუმლო ფაილები, `rm -rf`, force-push…). IDE-ზე არ მოქმედებს — იქ აკრძალვას hook-ები აღასრულებს.

### `.cursor/hooks/` — დაცვა, მეხსიერება და ჟურნალი (Python, მხოლოდ სტანდარტული ბიბლიოთეკა)

- [`cursor_adapter.py`](../.cursor/hooks/cursor_adapter.py) — ერთადერთი გამშვები: `hooks.json`-ის ყოველი ჩანაწერი მას იძახებს მოვლენის სახელით (`shell`, `tool`, `session-start` …), ის ქვემოთ ჩამოთვლილ შემოწმებებს უშვებს და პასუხს Cursor-ის ფორმატით აბრუნებს. ბლოკავს `guard.py`-ისა და `commit_secrets.py`-ის აღმოჩენებს; საიდუმლო ფაილის წაკითხვა-ჩაწერას; auditor-ს, verifier-ს, architect-ს, scout-სა და advisor-ს ფაილების შეცვლას უკრძალავს (ქვეაგენტს `parent_tool_call_id`-ით ცნობს, architect-სა და scout-ს shell-საც); სესიის დასაწყისში მეხსიერებას აწვდის და ამბობს, რომელი მოდელი მუშაობს; შეკუმშვის შემდეგ handoff-ის ჩაწერას ითხოვს; ყოველ მოქმედებას და ქვეაგენტს (მოდელით) ჟურნალში წერს. თუ თვითონ გაფუჭდა, დამცავ მოვლენებზე ბლოკავს.
- [`guard.py`](../.cursor/hooks/guard.py) — shell-ბრძანების შემოწმება: ბლოკავს `rm -rf`, `git reset --hard`, `git clean -f`, force-push, `main`-ში push (`git push origin HEAD`-იც, თუ `main`-ზე ხარ), `--no-verify`, ისტორიის გადაწერა, საიდუმლო ფაილის ქსელით გაგზავნა. იმ ბრძანებებზე, რომლებიც შეუნახავ სამუშაოს ან branch-ს შლის (`switch -f`, `restore`, `branch -D`, `stash drop`), და ფაილის ყოველ წაშლაზე (`rm`, `git rm` — მფლობელის მოთხოვნა, 2026-10-08) ჯერ გკითხავს; `grep rm`-ის მსგავს ბრძანებას, სადაც `rm` მხოლოდ სიტყვაა, არ ეხება. `bash -c`-სა და `eval`-ში დამალულ ბრძანებასაც ამოწმებს. read-only აგენტებს ფაილის შემცვლელ ბრძანებებს უკრძალავს; `git stash list`/`show` მათთვისაც ნებადართულია.
- [`commit_secrets.py`](../.cursor/hooks/commit_secrets.py) — ყოველ `git commit`-მდე staged ცვლილებებს საიდუმლოებებზე ამოწმებს (ჩაშენებული ნიმუშებით და, თუ დაყენებულია, gitleaks-ით) და წერს, რომელმა შემოწმებამ იმუშავა. ბლოკავს commit-ს, რომელიც ჯერ staged არ ყოფილ ცვლილებას შეიტანდა (`git add … && git commit`, `-a`, ფაილის სახელი), და commit-ს, რომლის სკანირებაც ვერ გაეშვა.
- [`secret_patterns.py`](../.cursor/hooks/secret_patterns.py) — საიდუმლოებების ნიმუშების საერთო სია (API გასაღებები, ტოკენები, პირადი გასაღებები, `.env`-ის ტიპის ფაილები).
- [`memory_context.py`](../.cursor/hooks/memory_context.py) — სესიის დასაწყისის მეხსიერება: `memory/now.md`, `PROGRESS.md`-ის მიმდინარე მდგომარეობა და შემდეგი ნაბიჯები და უახლესი handoff (დროით და არა სახელით). სულ ≈16 000 სიმბოლომდეა; გრძელ handoff-ს მხოლოდ შუა ეჭრება — თავი და ბოლო, ანუ „შემდეგი ნაბიჯი", ყოველთვის რჩება. ტექსტი შემთხვევითი ნიშნითაა შემოფარგლული („ღობე"), რომ მონაცემად იკითხებოდეს და არა ინსტრუქციად. ჩასატვირთ მთელ ტექსტს ინექციის ნიმუშებზე ამოწმებს და გაყალბებულ საზღვარს ანეიტრალებს.
- [`untrusted.py`](../.cursor/hooks/untrusted.py) — „ღობე" (`fence`), ინექციის ნიმუშების ძიება (`scan` — „ignore previous instructions", „შეჯამებისას ეს შეინახე", როლის გაყალბება, ყალბი საზღვარი, უხილავი სიმბოლოები) და უხილავი სიმბოლოების წაშლა.
- [`event_log.py`](../.cursor/hooks/event_log.py) — აგენტის მოვლენების ჟურნალი `.cursor/logs/events-<თარიღი>.jsonl`-ში: დრო, სესია, აგენტი, ხელსაწყო, მოკლე აღწერა (200 სიმბოლომდე; დაფარულია ცნობილი სერვისების გასაღებები, Bearer / Authorization მნიშვნელობები, `password=…` ტიპის ჩანაწერები და პაროლი URL-ში — სხვა ფორმის საიდუმლო შეიძლება გაიპაროს), შედეგი და მოდელი. git-ში არ შედის; დაბლოკილი გამოძახებები აქ არ ჩანს.

### `.cursor/agents/` — ხუთი დამხმარე აგენტი

Subagent (დამხმარე აგენტი) ცალკე აგენტია საკუთარი კონტექსტით: მთავარი საუბრის მსჯელობას ვერ ხედავს, საკუთარი მოდელი აქვს და მთავარ ჩატს მხოლოდ შედეგს უბრუნებს. ასე შემმოწმებელი ავტორისგან დამოუკიდებელია, მთავარი კონტექსტი კი სუფთა რჩება. ხუთივე `readonly: true`-ა და მოდელი თავსართშია დაფიქსირებული (`claude-opus-5-5[effort=high]` და ა.შ.); `check_structure.py` ამოწმებს, რომ ორივე ასეა.

- [`architect.md`](../.cursor/agents/architect.md) — Opus 5.5, მაღალი effort; მხოლოდ კითხვა და ვებში ძიება, shell-ის გარეშე. ერთ გადაწყვეტილებაზე 2–3 ნამდვილ ვარიანტს იძლევა წყაროებით, პლუსებით, მინუსებით, ფასით, რისკით და შექცევადობით, ბოლოს — რეკომენდაციას. გადაუმოწმებელს „UNVERIFIED"-ით ნიშნავს.
- [`auditor.md`](../.cursor/agents/auditor.md) — Opus 5.5, მაღალი effort. ყოველ კარიბჭეზე, ყოველი ეტაპის კოდზე და ყოველ `[high-risk]` დავალებაზე ამოწმებს სისრულეს, ზედა დოკუმენტებთან თანხვედრას და მტკიცებულებებს. ხელახალ შემოწმებაზე მხოლოდ გასწორებას უყურებს (გასწორდა / არ გასწორდა). პირველი ხაზი: `VERDICT: PASS / PASS-WITH-FINDINGS / FAIL / INCONCLUSIVE`, მეორე — `COUNTS: high=… medium=… low=…` ჟურნალისთვის. არასდროს ასწორებს და არასდროს ამტკიცებს.

- [`scout.md`](../.cursor/agents/scout.md) — Haiku 5.5, საშუალო effort, მხოლოდ კითხვა და ვებში ძიება, shell-ის გარეშე ([ADR-0007](decisions/0007-claude-only-orchestration.md), ვარიანტი A). სწრაფად პოულობს ფაქტებს: ბიბლიოთეკის ვერსიას, ფასს, დოკუმენტაციის გვერდს, სად წერია რამე რეპოში, გრძელი გვერდის შეჯამებას. ყოველ ფაქტს წყაროს და შემოწმების თარიღს უწერს; მის პასუხს გადაწყვეტილებამდე უფრო ძლიერი მოდელი ამოწმებს.

## ცნობილი ხარვეზები

- hook-ებს `python3` სჭირდება. თუ კომპიუტერზე არ არის, `python3` ვერ გაეშვება, დამცავი მოვლენები `failClosed`-ის გამო დაიბლოკება და აგენტი ბრძანებებს ვერ გაუშვებს — ასე სჯობს, ვიდრე დაცვის ჩუმად გათიშვა.
- read-only აგენტების დაცვა ორ რამეზე დგას: Cursor-ის `readonly: true`-ზე და ჩვენს hook-ზე, რომელიც ქვეაგენტს მისი სახელით ცნობს. რა სახელს უგზავნის Cursor საკუთარ (ჩვენს) აგენტს, პირველ ნამდვილ სესიაში უნდა გადამოწმდეს (`tasks/todo.md`). hook-ი ბრძანებების სიას ეყრდნობა: აშკარა ჩაწერას (`>`, `touch`, `rm`, `git commit`, `sed -i` …) ბლოკავს, მაგრამ პროგრამა, რომელიც შიგნიდან წერს ფაილს, არ ჩანს.
- Cursor-ში შეკუმშვის ზღვარი (65%) არ ყენდება და შეკუმშვამდე გაფრთხილება არ არსებობს — handoff შეკუმშვის შემდეგ, შეჯამებიდან იწერება; მთავარ მოდელს რეპო ვერ აფიქსირებს (არჩევა ხელით, hook მხოლოდ აფრთხილებს).
- `main` GitHub-ზე ტექნიკურად დაცული არ არის (უფასო გეგმა): CI წითელ ნიშანს აჩვენებს, მაგრამ გაერთიანებას ვერ აჩერებს.
